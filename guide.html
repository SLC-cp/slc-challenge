CHAPTER 01

WordPressの、ほんとに最低限

WordPressの解説書は分厚いですが、今回の作業に必要な知識は3つだけです。それ以外は、必要になったときに覚えれば十分です。

1テーマ＝「サイトの見た目一式」が入ったフォルダ

WordPressの見た目は「テーマ」というフォルダで決まります。今回配られる template_theme もただのフォルダで、中にPHP・CSS・JSのファイルが入っています。このフォルダを丸ごとコピーして改造するのが、SLCのサイト制作の基本形です。

2PHPファイル＝ところどころに「穴」があいたHTML

テーマの中の .php ファイルを開くと、見慣れたHTMLの中に <?php ... ?> という区間が混ざっています。ここはWordPressが後から中身を流し込む「穴」です。穴の中は今回いっさい触りません。穴の周りのHTMLとクラス名だけを、カンプに合わせて書き換えます。

3front-page.php＝トップページ、page.php＝下層ページ

「どのファイルがどのページになるか」はファイル名で決まっています。今回触るのはトップページ＝ front-page.php だけです。下層（page.php ほか）は次の研修で扱います。

「ループ」とか「フック」とか、WordPress用語はまだ知らなくていいよ。この3つさえ分かってれば今回の作業は全部できるから。
CHAPTER 02

作業環境をつくる
（お名前.comのテスト環境）

会社で用意している、お名前.comサーバー上のテスト用WordPressを使います。本物のサーバーで動く本物のWordPressです。ただし1つだけ、先に覚えてほしい原則があります。

原則テスト環境は「表示確認器」。あなたの成果物は、手元のテーマフォルダ

コードの正本（マスター）は常に自分のPCのテーマフォルダに置き、テスト環境には「zipにして流し込んで表示を見るだけ」という役割分担にします。この形なら、テスト環境がいつ初期化されても失うものはありません。逆に、WordPressの管理画面にある「テーマファイルエディター」で直接コードを書くのは禁止です——手元の正本とズレて、どちらが本物か分からなくなります。

3
入れたことを確認する外観 → テーマ の一覧が開ければ準備完了です。

テーマを反映する基本ループ（何十回もやります）

◎ 慣れてきた人向け：FTPで直接アップロードする方法

FileZillaなどのFTPソフトで wp-content/themes/nagashima-dc/ に接続すると、変更したファイルだけを転送できて速くなります（FTP情報は教育担当から）。ただし転送先を1階層間違えると他のフォルダを上書きします。まずはzipの基本ループで1周してからにしてください。

この章の 1 point

「テスト環境が消えても困らない形」で作業できていればOK

正本は手元のフォルダ、テスト環境は確認用。この分担さえ守れていれば、テスト環境に何が起きても被害ゼロです。テーマファイルエディターでの直接編集だけは、絶対にしないこと。

コードを書き始める前に、カンプ2枚（PC・SP）を開いて眺めます。実案件でもカンプは「画像＋この章のようなスタイルガイド」のセットで渡されます。章の終わりに、実案件で必ず出てくる「足りない素材の作り方」も付けました。

カンプの見方

PCとSPを並べて見る
同じセクションがPCとSPでどう変形するか（3列→1列、横並び→縦積み）を先に把握しておくと、CSSの書き方（メディアクエリ）が決めやすくなります
繰り返しの単位を探す
「強みの6枚」「診療項目の9枚」「医院紹介の3行」はどれも同じ部品の繰り返しです。1個ぶんのHTMLとCSSを作れば、残りはコピーで済みます。約22ブロックありますが、部品の種類はずっと少ないです
色数を数える
このカンプは実質5色（濃茶・金茶・ベージュ・白・グレー系の文字色）しか使っていません。下のスタイルガイドの変数に全部対応しています
背景のリズムを見る
白 → 斜めパターンのベージュ → 濃茶、の3種類の帯が交互に来る構成です。どのセクションがどの背景か、先に鉛筆でメモしておくと迷子になりません

参考サイトのCSSの覗き方（実案件で必ず使う技）

実案件では「このサイトみたいな雰囲気で」と参考サイトを渡されることがよくあります。そのとき、見た目から作り方を推測する必要はありません。ブラウザの開発者ツールで答えを直接見ることができます。今回の演習でも「カンプのこの部分、どう作るんだろう」と思ったら、似た作りのサイトで同じことをして構いません。

1
調べたい場所を右クリック →「検証」開発者ツール（DevTools）が開き、その要素のHTMLが選択された状態になります。左上の矢印アイコン（要素選択モード）をクリックしてからページ上を選び直すこともできます。
2
「Styles」タブで、当たっているCSSを読む選択中の要素に効いているCSSが上から優先順に並びます。取り消し線が付いた行は、他のCSSに上書きされて効いていない行です（下の図では、より強い .btn.line の background に負けた行に取り消し線が付いています）。右端の「style.css:198」は書いてある場所です。
3
実際の値は「Computed」タブで確認するStylesは「書いてあるCSS」、Computedは「最終的に適用された値」です。フォントの確定値は Computed の font-family、さらに下の「Rendered Fonts」を見ると、実際にどのフォントで描画されたかまで分かります（Webフォントが読めているかの確認にも使えます）。
4
色はスウォッチから拾うStylesの色付き四角（スウォッチ）をクリックするとカラーピッカーが開き、カラーコードをコピーできます。左下のスポイトアイコンを押すと、画面上の好きな場所の色を拾えます。
5
余白はハイライトの色で見る要素を選択すると、ページ上に margin がオレンジ、padding が緑で表示されます（下の図の左）。数値は Computed 上部のボックスモデル図（右）に出ています。「この余白、何pxだろう」はこれで一発です。
6
その場で書き換えて実験するStylesの値はクリックするとその場で編集できます（↑↓キーで1pxずつ増減。リロードすれば元どおり）。「この影を消したらどう見えるか」「このpaddingを増やしたら」を、コードを書く前に試せます。自分のテスト環境の調整にも同じ技が使えます——DevToolsで数値を調整して正解を見つけてから、style.cssに書き写すと速いです。
禁止「見て学ぶ」のはOK。「コピーする」のはNG

参考サイトから読み取っていいのは、値と仕組み（色・余白・フォント指定・レイアウトの作り方）までです。CSSやHTMLを丸ごとコピーして流用しない。写真・イラスト・アイコン・背景画像は1枚たりとも流用しない（著作物です）。文章もコピーしない。このラインは実案件では会社の信用に直結します。迷ったら講師に聞いてください。

カンプと1pxまで同じにならなくても大丈夫。見るのは色・フォント・余白のリズムが合ってるかどうか。そこが合ってれば「再現できてる」って言っていいよ。

背景画像とバナーは、ChatGPTでつくる

この研修では背景はCSSだけで作り（カンプの斜めベージュは linear-gradient を2枚重ねただけです）、写真は配布素材を使います。ただし実案件では「この帯にちょっと質感がほしい」「バナーの下地が足りない」が必ず出ます。そこで素材サイトを延々と探すより、ChatGPTの画像生成で作ってしまうほうが速い——これが今の会社の推奨です。ただし万能ではないので、使い分けを先に決めます。

生成でつくるもの
  • 背景のパターン・テクスチャ斜めストライプ、紙や布の質感、細かいノイズ
  • バナーの下地文字を載せる前の、抽象的な情景や色面
  • 一本線のアイコン・あしらい既製のピクトアイコンを拾ってくるより揃う
  • 仮あての風景・イメージ写真本番写真が届くまでのつなぎ。差し替え前提で
生成で作らないもの
  • 症例写真・ビフォーアフター医療広告ガイドライン。実在しない治療結果を出すのは論外です
  • 院内・スタッフ・院長の写真実在しない院内を載せると景表法の問題になります。実写のみ
  • ロゴベクターで作るもの。生成画像は輪郭が甘く、拡大に耐えません
  • 文字が入った画像日本語はまず崩れます。文字はHTML/CSSで載せる
1
先にCSSで作れないか考えるストライプ・ドット・単純なグラデーションは linear-gradient / repeating-linear-gradient で作れます。CSSで足りるならそのほうが軽く、色も後から1行で変えられます。画像に頼るのは「質感」が要るときだけ。
2
用途とサイズを決めてから頼む「タイルで繰り返す」のか「1枚で敷く」のかで作り方が変わります。タイルなら正方形（1024×1024など）、1枚敷きならセクションの実寸に近い横長で。
3
下の依頼文をコピーして、数値と色だけ書き換える色はカンプのスタイルガイドのコードをそのまま入れます。1回で決まらないのが普通なので、直すときは一度に1箇所だけ（「ストライプの間隔を2倍に」「四隅の暗さを消して」）。まとめて言うと別物が返ってきます。
4
継ぎ目と粗さを確認するタイルは実際にCSSで repeat して継ぎ目を見る。生成画像は完全なシームレスになりにくく、ここで諦めてCSSに戻る判断もよくあります。
5
圧縮してから入れる生成直後のPNGは数MBあります。Squoosh でWebPかJPGに変換し、背景は1枚200KB以下を目安に。ここを飛ばすと、せっかく作った背景がサイトを重くする原因になります。

APPENDIX

付録：つまずき集

先輩たちが実際に踏んだものだけを載せています。ここに無い詰まり方をしたら、それは新しい発見なので、解決したらこのリストに足してもらいます。

画面が真っ白になった
ほぼ100%、PHPファイルの書き間違いです（閉じタグの消し忘れなど）。直前に触ったファイルを、手元の正本と template_theme の元ファイルで見比べて戻す。分からなければ、そのファイルだけ元のtemplate_themeからコピーし直せば復旧します
CSSを直したのに変わらない
①zipを作り直さずに古いzipを上げていないか ②アップロード後に「置き換える」を選んだか ③ブラウザのスーパーリロード（Ctrl+Shift+R）を試したか、の順で確認。テーマ側のキャッシュ対策は自動なので、だいたい①です
フォントが明朝にならない
functions.php のWebフォントの区間が、コメントのままになっていないか確認（/* と */ が残っていたら、まだコメントです）。次に、basic.css の font-family のスペルを確認
SPメニューが開かない
#drawer-checkbox のIDを変えていないか確認。menu-header-sp.php を編集するとき、input と label の for 属性のペアを崩すと開閉が壊れます
画像が表示されない
PHPの中の画像パスは get_theme_file_uri( '/images/xxx.svg' ) という書き方になっています。既存の行をコピーして、ファイル名だけ変えるのが確実です。images/ にファイルを入れ忘れて zip を作っているパターンも多いです
アップロードが失敗する
まずもう一度試す（サーバー側の一時的な503はよくあります）。続くなら、zipの中に node_modules/ などの巨大フォルダが紛れていないか、zipがテーマフォルダ自体を包んでいるか（中身だけ圧縮していないか）を確認
テスト環境を壊したかも
慌てない。正本は手元のフォルダにあります。自分のテーマを入れ直して直るならそれでOK。直らない・他に影響していそうなら、それ以上触らずに教育担当へ。「何をしたら、どうなったか」をそのまま言えれば十分です
横スクロールが出る（SP）
幅を px で固定した要素が犯人です。開発者ツールで要素を1つずつ消しながら特定し、width を % や max-width に変えます
