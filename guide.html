CHAPTER 00

この手順書について

なにを作るのか、どこまでやるのか。最初に全体を見ておきます。1分で読めます。

ゴールは「カンプの再現」です。

配布フォルダの comp/comp-pc.jpg（PC幅1440px）と comp/comp-sp.jpg（スマホ幅375px）が、今回のデザインカンプです。実際に公開されている「永嶌歯科クリニック」のサイトデータ一式を預かり、トップページをこのカンプと見た目が一致するところまで作り替えます。下層ページは旧デザインのまま残します——実案件でよくある「トップ先行リニューアル」の形です。物量は実案件のトップと同じ、約22ブロックのフルボリュームです。

やること

やらないこと
サーバーへのアップロード（公開）はこの研修ではやりません。公開は手順も緊張感も別物なので、先輩と一緒にやる次の段階です。ほかに、下層ページの改修・共通部品（common/inc）への反映・お問い合わせフォーム・SEO設定・FVのスライダー化（JS）も今回は範囲外です
必要なスキル
HTMLとCSSが書けること。それだけです。サーバーの知識もJavaScriptも、今回は要りません
所要の目安
2〜3週間。実案件1本ぶんの物量なので、1日で終わるものではありません。速さより「どこまでできて、どこで詰まったか」を言えることのほうが大事です
配布物
この手順書（guide.html）／カンプ画像（comp/）／素材（material/ … ロゴSVG・写真23枚・手順書用の図解画像。写真はファイル名が使う場所の名前になっています。例：fv.jpg＝ファーストビュー、team.jpg＝スタッフ集合）。サイトデータ一式は配布しません——2章でFTPを使って自分でダウンロードします

CHAPTER 01

静的サイトの、ほんとに最低限

Web制作の解説書は分厚いですが、今回の作業に必要な知識は3つだけです。それ以外は、必要になったときに覚えれば十分です。

1サイト＝ただのフォルダ1個

今回預かる ndc-dental.jp は「静的サイト」——HTML・CSS・画像が入ったただのフォルダです。サーバーはこのフォルダの中身をほぼそのまま配信しているだけです。あなたの成果物も、リニューアル後のこのフォルダ丸ごと1個です。

2自分が書くパスは「相対」で書く

画像やCSSの場所は img/photos/fv.jpg のように、index.html から見た道順（相対パス）で書きます。既存ページには /common/img/... のような「ルート絶対パス」も出てきますが、これはサーバーに置いたときだけ効く書き方で、ローカルでダブルクリックした表示では効きません。今回自分が新しく書く部分は相対パスで統一します——トップページはフォルダの一番上にあるので、相対で書いてもサーバーに置いたときそのまま動きます。

3表示確認＝「保存 → ブラウザ再読み込み」

index.html をブラウザで開いておき、エディタで保存（Ctrl+S）するたびにブラウザを再読み込み（Ctrl+R）する。今回の確認方法はこれが全部です。アップロードもビルドも待ち時間もありません。

「デプロイ」とか「ビルド」とか、難しい用語はまだ知らなくていいよ。この3つさえ分かってれば今回の作業は全部できるから。
CHAPTER 02

作業環境をつくる
（複製とブラウザ）

エディタ（VS Code）・ブラウザ（Chrome）・FTPソフト（FileZilla）の3つを使います。サイトデータは配布されません——実案件と同じように、本番サーバーから自分でダウンロードするところから始めます。その前に、絶対の原則がひとつ。

原則FTPは「見る・落とす」だけ。サーバーには何ひとつアップロードしない

FTPソフトは、公開中の本番サーバーに直結しています。今回使っていいのはダウンロードだけです。サーバー側（右画面）へのドラッグ＆ドロップ・削除・リネームは絶対にしない。1回の誤操作が、そのまま公開中のサイトの事故になります。そしてダウンロードした一式はまず丸ごと複製してから作業を始めます。元のフォルダは何があっても戻れる保険なので、1文字も触りません。

最初のセットアップ

1
VS Code と FileZilla を入れるVS Codeは社内標準のエディタ、FileZillaは無料のFTPソフトです。すでに入っていれば飛ばしてください。インストールで詰まったら教育担当へ。
2
FTPの接続情報を受け取って、接続するホスト名・ユーザー名・パスワードを教育担当から受け取り、FileZillaの「サイトマネージャー」に登録して接続します。つながると、左＝自分のPC、右＝サーバーの中身が並びます。右側はもう本番です。眺める以外のことはしないでください。
3
サイト一式をダウンロードする自分のPCに空フォルダ ndc-dental.jp を作って左画面で開き、右画面（サーバーのルート）のフォルダ・ファイルを全選択して左へダウンロードします。ファイル数が多いので数分かかります。「失敗した転送」が出たら、最後にまとめて再試行してください。
4
複製して、作業フォルダにするダウンロードした ndc-dental.jp を丸ごとコピーし、フォルダ名を ndc-renewal に変えます。以後、このフォルダがあなたの正本です。元のフォルダはそのまま保管——何かあったらいつでもここへ戻れます。
5
VS Code でフォルダを開く「ファイル → フォルダーを開く」で ndc-renewal を開きます。以後の作業はぜんぶこの画面の中でやります。左側にファイル一覧が出ていれば準備完了です。

この章の 1 point

CHAPTER 03

サイトの構成を読む・
ひな形をつくる

コードを書く前に、預かったサイトが「どう出来ているか」を10分だけ眺めます。そのうえで、新しいトップページのひな形を作ります。ひな形のコードは考えずに、そのまま写して構いません。

全体の地図（複製した作業フォルダの中身）

ndc-renewal/
├─ index.html        ← トップページ。今回作り替える対象はこれだけ
├─ css/              ← トップ用CSS。ここに新しいCSSを足す
├─ img/              ← トップ用画像。ここにカンプの写真を足す
├─ common/
│   ├─ css/          ← 全ページ共通のCSS（cmn_style.css ほか）
│   ├─ img/・js/     ← 共通の画像とJS
│   └─ inc/          ← ヘッダー・フッターなどの共通部品（下で説明）
├─ concept/ staff/ implant/ price/ …
│   └─ index.html ＋ css/style.css ＋ img/  ← 下層ページ。全部この型
└─ contact/          ← お問い合わせフォーム（PHPプログラム入り）
1ページ＝1フォルダ
下層は「フォルダ＋index.html＋専用css/style.css＋専用img/」の型がずっと繰り返されています。どのページのファイルがどこにあるか、迷いようがない構成です
CSSは3層
①全ページ共通の common/css/cmn_style.css など ②下層共通の cmn_subpage.css ③各ページ専用の style.css。共通CSSを1行変えると全ページに効いてしまう——これが後の「触らない」ルールの理由です
仕組みヘッダーとフッターは「SSI」で差し込まれている

既存のHTMLを開くと <!--#include virtual="/common/inc/header.html"--> という行があります。これはSSI（サーバーサイドインクルード）——サーバーが配信の瞬間に共通部品を差し込む仕組みで、ヘッダー・フッター・共通CSSの読み込みは common/inc/ のファイルに1本化されています。だから既存ページをローカルでダブルクリックしても、ヘッダーもCSSも無い崩れた表示になります。壊れているわけではありません——サーバーに置いて初めて完成する書き方なのです。

方針新しいトップは「自己完結」で作る

今回のリニューアルでは、ヘッダーもフッターも新デザインに変わります。そこで新しいトップはSSIを使わず、1枚のindex.htmlの中に全部書きます。CSSも既存の共通CSSに頼らず、新規の css/top.css に全部書きます。こうすると①ローカルでダブルクリックするだけで完成形が確認できる ②既存の共通CSS・共通部品を一切触らないので、下層ページを壊しようがない ③トップはフォルダの一番上にあるので、相対パスのままサーバーに置いても動く——と、いいことずくめです。共通部品への切り出しと下層への展開は、次の段階で先輩とやります。

ひな形を書く

1
旧トップを保管するindex.html を index_old.html にリネームします。削除はしません——実装中に「元のトップはどう書いていたか」を覗ける、いちばん身近な参考書になります。
2
css/reset.css を作る下のコードをそのまま貼って保存します。ブラウザごとの標準スタイル（余白や点付きリスト）を消して、同じスタート地点に立つためのファイルです。
*,*::before,*::after{box-sizing:border-box;margin:0;padding:0;}
img{max-width:100%;height:auto;display:block;}
ul,ol{list-style:none;}
a{color:inherit;text-decoration:none;}
button,input,textarea,select{font:inherit;}
body{-webkit-text-size-adjust:100%;}
3
新しい index.html を作る下のコードをそのまま貼って保存します。<title> と <meta name="description"> は index_old.html の先頭からコピーしてください（SEOの資産なので勝手に変えません）。<main> の中のセクションを、6章で上から順に増やしていきます。
<!doctype html>
<html lang="ja">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>（index_old.html からコピー）</title>
<meta name="description" content="（index_old.html からコピー）">
<link rel="stylesheet" href="css/reset.css">
<link rel="stylesheet" href="css/top.css">
</head>
<body>
<header class="site-header"></header>
<main>
  <section class="fv"></section>
  <!-- ここにセクションを上から足していく -->
</main>
<footer class="site-footer"></footer>
</body>
</html>
4
css/top.css を新規作成して、先頭に「変数の枠」を作る下のコードをそのまま貼って保存します。いまは全部グレーの仮色です。本番の色に入れ替えるのは6章のSTEP 1でやります——ここでは枠だけ。既存の css/style.css は旧トップ用なので触らず、そのまま残します。
:root{
  --c-primary:#666666;      /* メインカラー */
  --c-accent:#999999;       /* アクセント */
  --c-cta:#666666;          /* ボタン地色 */
  --c-cta-hover:#444444;    /* ボタンhover */
  --c-bg:#ffffff;           /* ページ背景 */
  --c-surface:#eeeeee;      /* 色面の背景 */
  --c-border:#dddddd;       /* 罫線 */
  --c-text:#333333;         /* 本文文字 */
  --c-text-muted:#888888;   /* 補足文字 */
}
body{background:var(--c-bg);color:var(--c-text);}

/* ここからトップページのスタイルを実装 */
5
素材をコピーして、表示を確認する配布の material/logo.svg を img/ へ、material/photos/ の23枚を img/photos/（新規フォルダ）へコピー。最後に index.html をダブルクリックしてブラウザで開きます。真っ白なページでも、タブに「永嶌歯科クリニック」と出ていればひな形は成功です。
CHAPTER 04

触っていい場所・ダメな場所

動いているサイトのデータを預かる以上、ここが一番大事な章です。怖がらせたいわけではなくて、逆——「ここ以外は壊しようがない」と分かっていたほうが、思い切って書けます。

触っていい（今回の作業場所）
  • index.html新しいトップの中身ぜんぶ。ヘッダー → 約22ブロック → フッターを、カンプの上から順に
  • css/top.css（新規）新しいトップの見た目ぜんぶ。先頭に:root（色の変数）→ フォントなどの共通指定 → セクション順 → 末尾にSP用の@mediaを1つ、の順で書く
  • css/reset.css（新規・作ったら触らない）3章で作った土台
  • img/ロゴと写真の追加。既存ファイルは消さない（下層ページが使っている可能性があります）
触らない（理由つき）
  • common/css/ の cmn_*.css全ページ共通のCSS。1行変えると下層ぜんぶに効いてしまう
  • common/inc/全ページ共通のヘッダー・フッター部品（SSI）。ここの差し替えは本番反映とセットで、先輩とやる次の段階
  • concept/ などの下層フォルダ今回は旧デザインのまま並行稼働させる。1文字も触らない
  • contact/お問い合わせフォームのPHPプログラム。壊すと問い合わせが止まります
  • .htaccess・sitemap.xml などルートの設定ファイルサーバーの動きを決めるファイル。表示のリニューアルとは別の仕事
  • HTMLの style="" 属性への直書きあとから直せなくなる。スタイルは必ず top.css へ。色は var(--c-primary) のように変数で

まとめると、今回書き換えるのは index.html と、新規に作る css/top.css の実質2ファイルだけ。この2つの中では何を書いても、公開中の他のページを壊しようがありません。

CHAPTER 05

カンプを読む

コードを書き始める前に、カンプ2枚（PC・SP）を開いて眺めます。実案件でもカンプは「画像＋この章のようなスタイルガイド」のセットで渡されます。章の終わりに、実案件で必ず出てくる「足りない素材の作り方」も付けました。

カンプの見方

PCとSPを並べて見る
同じセクションがPCとSPでどう変形するか（3列→1列、横並び→縦積み）を先に把握しておくと、CSSの書き方（メディアクエリ）が決めやすくなります
繰り返しの単位を探す
「強みの6枚」「診療項目の9枚」「医院紹介の3行」はどれも同じ部品の繰り返しです。1個ぶんのHTMLとCSSを作れば、残りはコピーで済みます。約22ブロックありますが、部品の種類はずっと少ないです
色数を数える
このカンプは実質5色（紺・青・淡い青・白・グレー系の文字色）しか使っていません。下のスタイルガイドの変数に全部対応しています
背景のリズムを見る
白 → 斜めパターンの淡い青 → 紺、の3種類の帯が交互に来る構成です。どのセクションがどの背景か、先に鉛筆でメモしておくと迷子になりません

参考サイトのCSSの覗き方（実案件で必ず使う技）

実案件では「このサイトみたいな雰囲気で」と参考サイトを渡されることがよくあります。そのとき、見た目から作り方を推測する必要はありません。ブラウザの開発者ツールで答えを直接見ることができます。今回の演習でも「カンプのこの部分、どう作るんだろう」と思ったら、似た作りのサイトで同じことをして構いません。

1
調べたい場所を右クリック →「検証」開発者ツール（DevTools）が開き、その要素のHTMLが選択された状態になります。左上の矢印アイコン（要素選択モード）をクリックしてからページ上を選び直すこともできます。
2
「Styles」タブで、当たっているCSSを読む選択中の要素に効いているCSSが上から優先順に並びます。取り消し線が付いた行は、他のCSSに上書きされて効いていない行です（下の図では、より強い .btn.line の background に負けた行に取り消し線が付いています）。右端の「style.css:198」は書いてある場所です。
3
実際の値は「Computed」タブで確認するStylesは「書いてあるCSS」、Computedは「最終的に適用された値」です。フォントの確定値は Computed の font-family、さらに下の「Rendered Fonts」を見ると、実際にどのフォントで描画されたかまで分かります（Webフォントが読めているかの確認にも使えます）。
4
色はスウォッチから拾うStylesの色付き四角（スウォッチ）をクリックするとカラーピッカーが開き、カラーコードをコピーできます。左下のスポイトアイコンを押すと、画面上の好きな場所の色を拾えます。
5
余白はハイライトの色で見る要素を選択すると、ページ上に margin がオレンジ、padding が緑で表示されます（下の図の左）。数値は Computed 上部のボックスモデル図（右）に出ています。「この余白、何pxだろう」はこれで一発です。
6
その場で書き換えて実験するStylesの値はクリックするとその場で編集できます（↑↓キーで1pxずつ増減。リロードすれば元どおり）。「この影を消したらどう見えるか」「このpaddingを増やしたら」を、コードを書く前に試せます。自分の作っているページの調整にも同じ技が使えます——DevToolsで数値を調整して正解を見つけてから、top.cssに書き写すと速いです。
禁止「見て学ぶ」のはOK。「コピーする」のはNG

参考サイトから読み取っていいのは、値と仕組み（色・余白・フォント指定・レイアウトの作り方）までです。CSSやHTMLを丸ごとコピーして流用しない。写真・イラスト・アイコン・背景画像は1枚たりとも流用しない（著作物です）。文章もコピーしない。このラインは実案件では会社の信用に直結します。迷ったら講師に聞いてください。

カンプと1pxまで同じにならなくても大丈夫。見るのは色・フォント・余白のリズムが合ってるかどうか。そこが合ってれば「再現できてる」って言っていいよ。

背景画像とバナーは、ChatGPTでつくる

この研修では背景はCSSだけで作り（カンプの斜めの淡い青は linear-gradient を2枚重ねただけです）、写真は配布素材を使います。ただし実案件では「この帯にちょっと質感がほしい」「バナーの下地が足りない」が必ず出ます。そこで素材サイトを延々と探すより、ChatGPTの画像生成で作ってしまうほうが速い——これが今の会社の推奨です。ただし万能ではないので、使い分けを先に決めます。

1

2

3
下の依頼文をコピーして、数値と色だけ書き換える色はカンプのスタイルガイドのコードをそのまま入れます。1回で決まらないのが普通なので、直すときは一度に1箇所だけ（「ストライプの間隔を2倍に」「四隅の暗さを消して」）。まとめて言うと別物が返ってきます。
4
継ぎ目と粗さを確認するタイルは実際にCSSで repeat して継ぎ目を見る。生成画像は完全なシームレスになりにくく、ここで諦めてCSSに戻る判断もよくあります。
5
圧縮してから入れる生成直後のPNGは数MBあります。Squoosh でWebPかJPGに変換し、背景は1枚200KB以下を目安に。ここを飛ばすと、せっかく作った背景がサイトを重くする原因になります。

提出

作業フォルダ（ndc-renewal）をzipにして、教育担当に渡してください。index_old.html や下層フォルダは消さずにそのまま入れておきます。zipを受け取った人が、解凍して index.html を開くだけで新しいトップと同じ見た目になる——これが自己完結で作った成果物の完成条件です。渡す前に、上の「フォルダを動かしても表示できるか」をもう一度。あわせて、あなたのPCでも実際の表示を見てもらいます。

APPENDIX

付録：つまずき集

先輩たちが実際に踏んだものだけを載せています。ここに無い詰まり方をしたら、それは新しい発見なので、解決したらこのリストに足してもらいます。

index_old.html（旧トップ）や下層ページが崩れて表示される
正常です。既存ページはSSI（3章参照）でサーバーが共通部品とCSSを差し込む前提なので、ローカルで開くとヘッダーもスタイルも当たりません。壊したわけではないので、参考書として中身を読む分には問題ありません
CSSが1ミリも効いていない
ほぼ100%、<link> のパスの書き間違いです。href="css/top.css" のスペルと、top.css が本当に css フォルダの中にあるか（フォルダの外に作ってしまうミスが多い）を確認。ファイル名の .css が .css.txt になっているパターンもあります
CSSを直したのに変わらない
①保存したか（VS Codeのタブに「●」が付いていたら未保存） ②スーパーリロード（Ctrl+Shift+R）を試したか ③クラス名がHTML側と1文字ずつ一致しているか、の順で確認。だいたい①です
フォントが明朝にならない
<head> にGoogle Fontsの <link> が3行入っているか確認。次に font-family のスペル（Shippori Mincho）。開発者ツールの Computed → Rendered Fonts を見れば、実際にどのフォントで描画されたか分かります
SPメニューが開かない
input の id と label の for が一致しているか確認。次にHTMLの並び順——#drawer-check:checked ~ .drawer の ~ は「あとに続く兄弟」にしか効かないので、input がドロワーより上に、同じ親の中にある必要があります
画像が表示されない
相対パスの綴り（img/photos/fv.jpg）と、img/ へのコピー忘れを確認。大文字小文字の違い（fv.jpg と FV.jpg）は、自分のPCでは表示できてもサーバーに上げた瞬間に壊れるので、今のうちに揃えるクセを付けてください
横スクロールが出る（SP）
幅を px で固定した要素が犯人です。開発者ツールで要素を1つずつ消しながら特定し、width を % や max-width に変えます
